> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the app at `astroapp.midnightpoetry.studio`. It includes:
- accounts: email and password, optional TOTP 2-step and Turnstile;
- guest and member daily draws: the 1-card spread and the two-stage 3-card spread;
- reveal with the card meanings, and a Verify screen;
- the Journal, Patterns and 7-day check-ins.

It runs on Neon, and Cloudflare Workers Builds migrates the database and deploys it.

**Architecture:**
- A Next.js 16 App Router app (`apps/app`) runs as a Cloudflare Worker through OpenNext. Server code reaches Neon through Hyperdrive with Drizzle on `postgres` (postgres.js).
- Better Auth owns accounts and sessions in the same database.
- All draw logic runs on the server, in `apps/app/lib/draw`, using `@astro/draw`. Deck orders and salts never leave the server until a reading is complete.
- Card text lives in a new content package, `@astro/meanings`. Card visuals move from the landing app into `@astro/ui`, so both apps share them.

**Tech Stack:**
- App: Next.js 16.4, @opennextjs/cloudflare 1.20, Wrangler 4.168
- Data: drizzle-orm 0.45, drizzle-kit 0.31, postgres 4.1
- Accounts and email: better-auth 1.7 (two-factor, captcha and haveibeenpwned plugins), Resend 6
- Checks and tests: Zod 4, Vitest 5, Playwright 1.65, and `otpauth` (tests only)

## Global Constraints

- **Draws:**
  - Fisher–Yates with `crypto.getRandomValues`, run on the server before the pick.
  - The order is never sent to the browser before the reading is complete.
  - The 3-card spread picks in two stages, with separate shuffles: 3 positions from the 22 Majors, then 3 from the 56 Minors.
- **Fingerprint:**
  - It is the first **32** hex characters of `SHA-256(order.join(",") + "|" + orientations.join(",") + ":" + salt)`.
  - The salt is 16 random bytes in hex.
  - It is displayed as 8 groups of 4, before the pick.
  - The order, orientations and salt are revealed only after the reading is complete.
- **Reversals:** on by default, at rate **0.30**, read from the `app_setting` row `reversal_rate`.
- **Daily limit:**
  - One reading per spread per calendar day, in the person's timezone, with no reshuffle.
  - Guests: the 1-card spread only, not saved to a journal, deleted 48 h after creation.
- **Tiers:** a free account adds the 3-card spread, the Journal, Patterns and check-ins. Paid tiers are Plan 3; show "Go deeper" as a link only.
- **Accounts:**
  - Email and password only, with no Google sign-in.
  - Passwords are at least 12 characters and are checked against the haveibeenpwned range API.
  - Email must be verified before first sign-in.
  - TOTP 2-step is optional for users.
  - Turnstile protects sign-up, sign-in, password-reset requests and guest draw starts.
- **Security:**
  - Zod validates every input.
  - Every state-changing route checks that `Origin` equals `APP_URL`.
  - There is a nonce-based CSP. Headers: HSTS, `nosniff`, `frame-ancestors 'none'`, Referrer-Policy `strict-origin-when-cross-origin` and Permissions-Policy.
  - No secret goes in the repo or in GitHub.
  - The runtime database role is `astro_web` (no DDL). Migrations run as `migrator` from the Workers Builds deploy command.
- **Design:**
  - Tokens come from `@astro/tokens`.
  - Fonts: Cormorant Garamond for display, Inter for UI, self-hosted.
  - UI transitions stay at or under 300 ms, with the easings `--ease-out` and `--ease-in-out`.
  - Reduced motion keeps fades and removes movement.
  - Accessibility: WCAG 2.2 AA, touch targets of at least 44 px, and layouts work at 360 px.
- **Performance:** under 200 KB of gzipped first-load JS on every app route, and no three.js or GSAP in the app.
- **Copy:**
  - The disclaimer "For reflection and entertainment. Not a substitute for medical, legal or financial advice." appears on every reveal.
  - Meanings use "may", "invites" or "suggests", never fate or certainty, and give no health, legal or financial advice.

## Review Focus

1. **Racing requests:** two tabs, or a double-tap, start a draw or pick at the same time. There must be exactly one session per person, spread and day, and repeating a pick returns the same cards rather than new ones.
2. **Timezone games:**
   - A guest who sends a different `timeZone`, or a member who changes their timezone, must not get a second reading that day.
   - Members can change their timezone once every 7 days.
   - Guests are limited by their guest cookie and by an IP-hash daily cap.
3. **Order leaks before completion:** no API response, HTML or RSC payload may contain `order`, `orientations` or `salt` while a session is unfinished. That includes error messages and the Verify page.
4. **Account enumeration:** sign-up, sign-in and password reset must answer the same way whether or not the email exists.
5. **Credential changes:** a password reset or change, or turning 2-step off, revokes every other session. Backup codes work once.

Each line has its test in the task that owns the code: Task 7 for 1–3, Task 6 for 4–5.

**Files:**

- Test: `apps/app/test/draw-service.test.ts` (integration, `DATABASE_URL_TEST`)

**Interfaces:**
- Consumes:
  - from `@astro/draw`: `createDeck`, `pickAt`, `localDay`, `isTimeZone`, `nextLocalMidnight`;
  - from `@astro/cards`: `allCards`;
  - `getSessionUser` and `getDb`.
- Produces:
  - `type Actor = { kind: "user"; userId: string; timeZone: string } | { kind: "guest"; guestHash: string; ipHash: string; timeZone: string }`.
  - `startDraw(db, actor, spread: "one"|"three", now: Date): Promise<StartResult>`. `StartResult = { sessionId, spread, decks: { stage, size, fingerprint }[] }`. When today's session exists it returns that session unchanged, which makes it idempotent.
  - `pick(db, actor, sessionId, stage, positions: number[]): Promise<{ cards: { cardId, orientation }[] }>`. Repeating the same positions returns the same cards. Different positions after a stage is done raise `DrawError("stage_done")`.
  - `getReading(db, actor, sessionId)`. It returns cards for completed stages and fingerprints, and `reveal: { order, orientations, salt }[]` **only when `status = 'complete'`**.
  - `DrawError` codes: `daily_limit` (with `resetsAt` ISO), `guest_spread`, `bad_positions`, `wrong_stage`, `stage_done`, `not_found`, `rate_limited`.
  - Guests:
    - The `astro_guest` cookie holds 32 random hex characters and is `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=172800`.
    - `guestHash = sha256(cookie)`.
    - `ipHash = sha256(cf-connecting-ip + daily salt)`, where the daily salt is derived from `BETTER_AUTH_SECRET` and the UTC date.
    - The cap is 3 guest readings per `ipHash` per local day.
    - Guest sessions older than 48 h are deleted at each guest start, `limit 200`.
  - Timezone:
    - for a member, the stored value;
    - for a guest, the request's `timeZone` if `isTimeZone`, else `UTC`.
    - The `local_day` is computed once, at start, and stored.

Rules:
- **`one`:** one deck of all 78 cards (`stage: "single"`), with 1 position.
- **`three`:** members only. It has two decks, both created at start, so both fingerprints show before any pick: `majors` (22) and `minors` (56). Pick 3 Majors first, then 3 Minors. The session completes after the last stage.
- **Reversal rate:** comes from `app_setting`.

The routes:
- **Start:** `POST /api/draw/start {spread, timeZone, turnstileToken?}`. Guests must send a Turnstile token, verified with `siteverify`, and pass the `GUEST_DRAWS` rate limit keyed by `ipHash`.
- **Pick:** `POST /api/draw/pick {sessionId, stage, positions}`.
- **Read:** `GET /api/draw/:id`.
- **Checks:** every route runs Zod and `assertSameOrigin`, and never puts `order`, `orientations` or `salt` in an error message.
